### Regras do `arch` (camadas MVC)

Aplicadas pelo dependency-cruiser:
- `no-circular`: proibido ciclo de imports.
- `models-are-pure`: `src/models/**` não importa `controllers`, `routes`, `middlewares`, `app`, nem `express`.
- `controllers-not-routes`: `src/controllers/**` não importa `routes` nem `app`.
- `routes-only-wire`: `src/routes/**` não importa `models` (a rota só aponta para o controller).
- `no-orphans`: todo arquivo de `src/` precisa ser alcançável (exceto `server.ts`, que é o ponto de entrada).
- `not-to-tests`: `src/` nunca importa `tests/`.

Aplicadas pelo `scripts/check-architecture.mjs` (regras que o dependency-cruiser não consegue expressar):
- `process.env` só pode ser lido em `src/config/env.ts`.
- `app.listen` só pode aparecer em `src/server.ts` (composition root). Assim o `app.ts` continua testável.

## Orquestração

`scripts/runGate.mjs` — registro `{ id, label, run }`, do mais barato ao mais caro, parando na primeira falha (exit 1):

```
typecheck → lint → build → arch → tests → deadcode
```

- `npm run gate` → todos os gates.
- `npm run gate:<id>` → um gate isolado.
- `node scripts/runGate.mjs <id> [<id>...]` → um subconjunto, que é o que o evaluator vai usar a partir do `contract.md`.
